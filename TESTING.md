## Цель тестирования

Убедиться, что после переноса сайта на Spring Boot:

- сервис `MovieService` корректно возвращает список фильмов, находит фильм по ID и обрабатывает отсутствие фильма;
- контроллеры отдают главную страницу, страницы фильмов, REST API и правильные HTTP-статусы (200 / 404 / 400);
- репозиторий `MovieRepository` сохраняет и читает данные из базы H2;
- приложение целиком запускается, база заполняется 18 фильмами сайта, все постеры и страницы доступны.

## Используемые инструменты

| Инструмент        | Назначение                                                   |
|-------------------|--------------------------------------------------------------|
| JUnit 5 (Jupiter) | фреймворк тестов, аннотации `@Test`, `@DisplayName`          |
| Mockito           | mock-объекты репозитория и сервиса                           |
| AssertJ           | читаемые проверки `assertThat(...)`                          |
| Spring Boot Test  | `@WebMvcTest`, `@DataJpaTest`, `@SpringBootTest`             |
| MockMvc           | HTTP-запросы к контроллерам без запуска реального сервера     |
| H2 (профиль test) | отдельная тестовая база `jdbc:h2:mem:kinopoisk_test`         |

## Виды тестирования

1. **Модульное (unit)** — `MovieServiceTest`: сервис проверяется изолированно, репозиторий заменён mock-объектом.
2. **Тестирование веб-слоя** — `MovieControllerTest` (`@WebMvcTest`): поднимается только MVC, сервис — mock.
3. **Тестирование слоя данных** — `MovieRepositoryTest` (`@DataJpaTest`): реальная JPA и H2, транзакции откатываются.
4. **Интеграционное** — `KinopoiskApplicationTests` (`@SpringBootTest`): всё приложение с заполненной базой.
